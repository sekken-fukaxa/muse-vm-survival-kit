# 実地で踏んだ罠と対策 15件

すべて 2026-11-04 の実作業で実際に起きたことです。「起きたこと → 原因 → 対策」の順で書きます。

## 1. 導入作業の最中に VM が入れ替わった

- **起きたこと**: ツール導入の途中で VM が交換され、apt で入れたもの（tesseract、pandoc、mkvtoolnix 等）と `/tmp` の作業物が全部消えた
- **原因**: VM は使い捨てが前提の基盤。タイミングは選べない
- **対策**: 永続の正は `~/workspace/` のみ。apt 側は `reinstall.sh` で再現可能な状態にしておく。実際、この対策のおかげで道具箱は全復旧した

## 2. ランタイムの自動復旧が apt ロックを握って離さない

- **起きたこと**: VM 入替後、ランタイムが apt パッケージの自動復旧（意図の再実行）を始めるが、ミラー不調で `apt-get update` が数十分止まり、その間こちらの apt が全部ロックで弾かれた
- **対策**: `reinstall.sh` の先頭にロック待ちループを入れる（[bin/wait-apt-lock.sh](../bin/wait-apt-lock.sh)）。「ロックされている＝失敗」ではなく「待てばよい」

## 3. apt ミラーが不安定

- **起きたこと**: 初回の apt 導入が接続失敗で 25 分かかって失敗。小さな graphviz 1つでも 14 分かかった日がある
- **対策**: `Acquire::Retries=5` と HTTP タイムアウト延長を常時指定。失敗してもスクリプトを再実行すれば冪等に続きから進む設計にする

## 4. egress プロキシの CA が Python から見えない

- **起きたこと**: yt-dlp 等が `CERTIFICATE_VERIFY_FAILED`。VM の外向き通信はプロキシ経由で、その CA は自己署名系
- **対策**: プロキシ CA（`/run/hatch/egress-tls/hatch-egress-ca.pem`）を venv の certifi バンドルに追記する（[bin/add-proxy-ca.sh](../bin/add-proxy-ca.sh)）。ただし証明書を直してもサイトによってはタイムアウトする（次の件）

## 5. VM シェルから届かないサイトがある

- **起きたこと**: YouTube への直接取得は SSL 修正後もタイムアウトが続き、安定しなかった
- **教訓**: 「VM から直接取る」経路はサイト相性がある。前提にせず、ブラウザ経由など代替経路を持つ。届かないことを「存在しない」と混同しない

## 6. Playwright の Chromium はプロキシを通れない

- **起きたこと**: 補助ブラウザとして入れた Playwright で、Chromium だけ `ERR_TUNNEL_CONNECTION_FAILED`。curl と Firefox は同じプロキシで通る
- **対策**: 実サイト取得の既定エンジンを Firefox にする。Chromium はローカル描画専用と割り切る。なおプロキシ認証情報は URL に埋め込まず、`username`/`password` フィールドに分けて渡す必要があった

## 7. 依存バージョンの固定は命綱

- **起きたこと**: faster-whisper 1.2.1 は PyAV 19.x と API 非互換で、`av==16.1.0` に固定しないと動かなかった
- **対策**: 動いた組み合わせはバージョンを明記して固定し、理由をコメントに残す。「最新に上げたら壊れた」を防ぐ

## 8. 依存が衝突したら venv を分ける

- **起きたこと**: markitdown（Pillow>=12.2 要求）と moviepy（Pillow<12 要求）が同じ venv で衝突
- **対策**: 無理に共存させず、用途ごとに専用 venv を作って `bin/` にリンクする。venv はホーム内なので永続するし、分離自体は安い

## 9. 道具ごとに「相性の悪い組み合わせ」がある

- **起きたこと**: OCRmyPDF に高精度 tessdata_best を指すと、エラーなく**テキスト層が空**の PDF ができた（標準 tessdata では正常）
- **教訓**: 「エラーが出ない失敗」が一番怖い。導入テストは必ず出力の中身まで検める（OCR なら読み戻し、バックアップなら復元、暗号化なら復号）

## 10. Hugging Face ハブ経由のダウンロードが詰まる

- **起きたこと**: whisper モデルの取得がハブ経由で進まず、ファイル直リンクを curl で取る経路に切り替えて成功
- **対策**: モデルは「取得できたら勝ち」ではなく、ローカルに置いて再取得不要にする。取得経路は複数持つ

## 11. 大物データこそホーム内に

- **対象例**: VOICEVOX エンジン約 3.9GB、whisper モデル、Playwright ブラウザ約 1GB、辞書類
- **対策**: 全部 `~/workspace/tools/` 配下。ディスクは 150GB 級あることが多いので、遠慮せず置く。逆に `/usr` 側に置いた大物は入替で確実に消える

## 12. apt の日本語フォントは薄い

- **起きたこと**: IPA フォントや M PLUS 系は apt の標準リポジトリに無かった
- **対策**: 公式配布元（IPA、Google Fonts）から TTF を直接取得して `tools/fonts-extra/` に永続配置し、`~/.local/share/fonts/` へシンボリックリンク＋ `fc-cache`。ただし `~/.local` 自体は永続しないので、リンクの再作成は `reinstall.sh` の仕事

## 13. 「入った」と「使える」の間には実テストがある

- **実例**: ずんだもん TTS は合成音声を whisper で読み戻して内容一致を確認。restic は保存→復元→差分なしを確認。Marp の PDF 出力は補助ブラウザの Chromium を `CHROME_PATH` に指定しないと動かなかった（ラッパーで自動化）
- **対策**: 導入の完了条件を「往復が閉じること」と定義する。片道だけの確認は未完了

## 14. ユーザーのデータは「図書館＋メタ情報」で守る

- **やったこと**: 55MB の投稿ログ CSV を、検証済みの正規版＋メタ情報カード（Markdown）＋機械可読メタデータ（JSON、SHA-256 つき）で図書館領域に登録
- **理由**: チャットの添付はスレッドに埋もれる。「渡したかどうか」を後から即答でき、二重解析を防げる場所が要る

## 15. reinstall.sh は「導入と同時に」更新する

- **原則**: 新しい道具を入れたら、その場で対応する節を追記し、可能なら節単位で実行して確かめる
- **理由**: 後でまとめて書こうとすると、バージョン固定の理由や取得 URL のような肝心の情報が失われる。スクリプト自体が一番正確な作業記録になる
